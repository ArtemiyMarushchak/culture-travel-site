# SEO

Сайт статичный; мета и служебные файлы генерирует сборка (`tools/build.mjs`).

Публичный домен: **https://culture-travel.ru**

Основной поисковик для работы с индексом — **Яндекс** ([Яндекс.Вебмастер](https://webmaster.yandex.ru/)).

---

## Что уже есть на сайте

| Файл / механизм | URL / где | Зачем |
|-----------------|-----------|--------|
| `robots.txt` | `/robots.txt` | Разрешает обход, указывает sitemap |
| `sitemap.xml` | `/sitemap.xml` | Список публичных страниц |
| `llms.txt` | `/llms.txt` | Краткая карта сайта для AI (Markdown + ссылки) |
| Title / description | в `<head>` каждой страницы | Сниппет в поиске |
| Open Graph | meta `og:*` | Превью в мессенджерах / соцсетях |
| Canonical | `rel="canonical"` | Канонический URL на culture-travel.ru |
| `noindex` | заглушки и служебные | Не индексировать «в разработке» |

Проверка вручную:

- https://culture-travel.ru/robots.txt  
- https://culture-travel.ru/sitemap.xml  
- https://culture-travel.ru/llms.txt

## Яндекс.Вебмастер (основной чеклист)

1. Добавить сайт `https://culture-travel.ru`.
2. Подтвердить права (meta / файл / DNS — как предложит Вебмастер).
3. Отправить карту сайта: `https://culture-travel.ru/sitemap.xml`.
4. Дождаться обхода; при переезде с Тильды индекс обновляется **днями и неделями** — это нормально.
5. При необходимости — «Переобход страниц» для главной и ключевых URL.

Полезные разделы Вебмастера:

- Индексирование → Файлы Sitemap  
- Индексирование → Страницы в поиске  
- Диагностика → Важные проблемы

## Какие страницы в индексе

**Обычно index:**

- `/` — главная  
- `/news/{slug}/` — новости  
- `/cases/{slug}/` — публичные кейсы  
- отдельные публичные страницы из `pages/`, если не стоит `noindex`

**noindex (заглушки / служебное):**

- `/cruises/`, `/tours/`, `/hotels/` — «Страница находится в разработке» (`noindex`)
- закрытые программы для туристов (если в `page.json` указано `"robots": "noindex"`)
- `/404/`

Когда раздел готов к запуску: в соответствующем `pages/*.page.json` уберите `noindex` и подключите нужные блоки (см. [ADMIN.md](ADMIN.md)).

## Откуда берутся title и description

1. Дефолты — `core/site.json` → блок `seo` + `seo/defaults.json`.
2. Переопределение — в `pages/*.page.json` или в JSON контента (новость, кейс).
3. Сборка подставляет значения в layout.

OG-картинка по умолчанию:  
`core/site.json` → `seo.defaultOgImage` → файл в `assets/images/og/`  
(сейчас `/assets/images/og/default.webp`, ориентир 1200×630).

## `llms.txt`

Генерируется из шаблона `seo/templates/llms.txt.template`.  
Формат: Markdown с заголовком и **ссылками** вида `[текст](url)` — так файл понимают и люди, и AI-краулеры.

После смены структуры сайта просто пересоберите — `llms.txt` обновится в `dist/`.

## Переезд с Тильды

Если домен только что указывал на Тильду:

- в выдаче ещё могут быть старые URL и сниппеты;
- DNS у части пользователей может кэшировать старый IP (см. [DEPLOY.md](DEPLOY.md));
- ускорить можно переобходом в Вебмастере и корректным 301 на стороне старого хостинга (если ещё доступен).

На новом сайте каноникалы и sitemap уже на culture-travel.ru.
