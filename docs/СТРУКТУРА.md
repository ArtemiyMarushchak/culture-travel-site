# Структура репозитория — 7 папок

> **Один репозиторий = один статичный сайт.**  
> CRM, ЛK, docs — **отдельные репозитории позже** (см. `docs/ЭКОСИСТЕМА.md`).

В корне проекта **только эти 7 папок** (+ `dist/` результат сборки, + `preview/` для локального просмотра):

```
culture-travel-site/
├── 1. core/              ← ядро: JS + сборщик + конфиг
├── 2. styles/            ← глобальные стили: токены, шрифты, отступы
├── 3. assets/            ← фото, видео, favicon, woff2, иконки
├── 4. blocks/            ← блоки ГЛАВНОЙ страницы
├── 5. blocks-secondary/  ← блоки второстепенных страниц
├── 6. seo/               ← всё для SEO
├── 7. pages/             ← страницы сайта + данные кейсов/новостей
└── dist/                 ← готовый сайт (не коммитим)
```

---

## 1. core/ — ядро

**Мозг сайта.** JS, конфиг, сборщик.

```
core/
├── build.mjs              ← сборщик (JSON + блоки → dist/)  [сейчас: tools/build.mjs]
├── init.js                ← старт в браузере
├── registry.js            ← какой блок как инициализируется
├── anchors.js             ← плавный scroll к якорям
├── video-overlay.js       ← hero-видео при скролле
├── site.json              ← телефон, email, юр. данные, домен
├── nav.json               ← пункты меню
├── blocks.registry.json   ← каталог всех блоков (main + secondary)
└── layouts/
    └── default.html       ← оболочка HTML-страницы
```

| Файл | За что отвечает |
|------|-----------------|
| `build.mjs` | Собирает страницы, sitemap, robots, копирует assets |
| `init.js` | Находит `[data-block]` на странице, вызывает JS блоков |
| `registry.js` | `header` → initHeader, `modal` → initModal… |
| `site.json` | Контакты, SEO defaults, URL сайта |
| `page-layout.json` | Header + footer на каждой странице автоматически |
| `content-types.json` | Привязка: news/cases/hotels → карточка + страница |
| `blocks.registry.json` | Какие CSS/JS у каждого блока, откуда данные |

## 4. blocks/ — блоки главной страницы

Каждый блок = папка с **HTML + CSS + JS** (JS — если нужен).

| Папка | Блок |
|-------|------|
| `header/` | Шапка |
| `hero-video/` | Hero с видео |
| `about/` | Обо мне |
| `cases-slider/` | Кейсы (слайдер на главной) |
| `services/` | Услуги |
| `reviews/` | Отзывы |
| `contact-footer/` | Блок «Связаться» перед футером |
| `footer/` | Футер |

**Главная** (`pages/index.page.json`) собирается из этих блоков:

```
header → hero → about → cases-slider → services → reviews → contact-footer → footer → modal
```

---

## 5. blocks-secondary/ — второстепенные страницы

Тот же формат: **HTML + CSS + JS** на блок.

| Папка | Где используется |
|-------|------------------|
| `brochure/` | Бизнес-авиация, Круизы (лендинг-секции) |
| `hotel-catalog/` | Страница «Отели» |
| `news-list/` | Список новостей |
| `news-layout/` | **Отдельная** страница одной новости |
| `case-layout/` | **Отдельная** страница одного кейса |
| `legal-page/` | Политика обработки данных |
| `error-404/` | Страница ошибки |
| `modal/` | Попапы (фото/видео отелей) |
| `contact-card/` | **Онлайн-визитка** (/contact/) |

> **Кейсы и новости на отдельных URL** — шаблон блока здесь (`case-layout`, `news-layout`),  
> а **уникальный текст/фото** — в `pages/data/cases/` и `pages/data/news/`.

## 7. pages/ — страницы сайта

### Header + Footer на каждой странице

**Не прописываешь вручную.** Build читает `core/page-layout.json`:

```
header → [твои блоки] → footer → modal
```

Исключение: `/contact/` — `"layout": "minimal"` (визитка без шапки).

Подробно: **`docs/КОНТЕНТ.md`**

### Один JSON → карточка + страница

| Тип | Папка | Карточка | Страница |
|-----|-------|----------|----------|
| Новость | `content/news/` | `/news/` | `/news/slug/` |
| Кейс | `content/cases/` | главная (слайдер) | `/cases/slug/` |
| Отель | `content/hotels/` | `/hotels/` | `/hotels/slug/` |

Создал файл по `_template.json` → build всё связал сам.

---

### Список страниц (рецепты сборки)

| Файл | URL | Блоки |
|------|-----|-------|
| `index.page.json` | `/` | blocks/ (главная) |
| `news.page.json` | `/news/` | header, news-list, footer |
| `hotels.page.json` | `/hotels/` | header, hotel-catalog, footer |
| `business-aviation.page.json` | `/business-aviation/` | header, brochure, footer |
| `cruises.page.json` | `/cruises/` | header, brochure, footer |
| `privacy.page.json` | `/privacy/` | header, legal-page, footer |
| `contact.page.json` | `/contact/` | contact-card (визитка) |
| `404.page.json` | `/404/` | error-404 |

**Добавить страницу** → новый `*.page.json` + при необходимости блок в `blocks-secondary/`.

### Данные кейсов и новостей (много страниц)

```
pages/
├── index.page.json
├── contact.page.json
├── …
└── data/
    ├── cases/
    │   ├── _template.json     шаблон для нейросети
    │   └── example-case.json  → URL /cases/example-case/
    └── news/
        ├── _template.json
        └── welcome.json       → URL /news/welcome/
```

**Добавить кейс** → новый JSON в `pages/data/cases/` → build создаёт `/cases/slug/`.  
**Добавить новость** → JSON в `pages/data/news/` → `/news/slug/`.

> Сейчас данные ещё в `content/` — **переедут** в `pages/data/` после OK.

---

## Как сборка соединяет всё

```
pages/index.page.json          ← какие блоки
        +
blocks/header/header.html      ← шаблон
        +
core/site.json                 ← телефон, email
        +
styles/tokens/colors.css       ← цвета
        +
assets/images/…                ← фото
        ↓
   core/build.mjs
        ↓
   dist/index.html              ← готовая страница
```

---

## Что куда НЕ кладём

| ❌ Не смешиваем | Почему |
|----------------|--------|
| Тексты кейсов в `blocks/` | Блок = шаблон, текст = `pages/data/` |
| Фото в `styles/` | Только CSS |
| SEO meta в блоках | Только `seo/` + JSON страницы |
| CRM / Supabase | Другой репозиторий |
