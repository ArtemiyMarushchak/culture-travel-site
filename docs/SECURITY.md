# Безопасность публичного репозитория

## Главное — коротко

**Чужие люди не могут изменить ваш живой сайт**, если вы им не дали доступ.

| Действие | Может ли случайный человек с GitHub? |
|----------|--------------------------------------|
| Посмотреть код репозитория | ✅ Да (репо публичный) |
| Сделать **fork** (копию у себя) | ✅ Да — это **другой** сайт, не ваш |
| **Push** в ваш `main` и изменить сайт | ❌ **Нет** |
| Отправить Pull Request | ✅ Да — но **вы** решаете, мержить или нет |
| Изменить GitHub Pages по вашему URL | ❌ **Нет** без доступа к аккаунту/репо |

Сайт обновляется **только** когда кто-то с правами записи пушит в `main` → срабатывает Actions → деплой.

## Публичный репо — что видно, что нет

### Видно всем на GitHub

- Исходный код (HTML, CSS, JS, JSON)
- История коммитов
- То же, что и на собранном сайте (контакты в footer, тексты кейсов)

### Не должно попадать в git (уже в `.gitignore`)

| Файл | Почему |
|------|--------|
| `.env`, `.env.*` | API-ключи, пароли |
| `*.pem`, `*.key` | SSH/TLS ключи |
| `secrets/` | любые секреты |
| Personal Access Token | **никогда** в коде — только в менеджере паролей |

GitHub **Token** для push храните только у себя. Если утёк — сразу Revoke в GitHub → Settings → Developer settings → Tokens.

### Контакты и реквизиты в `core/site.json`

Телефон, email, ИНН, ОГРН — **публичные данные компании**, они и так на сайте в footer. Это нормально для юрлица.  
**Не** кладите в репо: пароли, ключи CRM, личные заметки клиентов.

## Защита — что включить (чеклист)

### 1. Двухфакторная аутентификация (2FA)

GitHub → **Settings → Password and authentication → Two-factor authentication** → включить.

Без 2FA взлом пароля = полный контроль над репо и сайтом.

### 2. Никому не давать write-доступ без нужды

GitHub → репозиторий → **Settings → Collaborators**

- **Read** — только просмотр (можно разработчику на время)
- **Write** — может пушить и менять сайт
- **Admin** — полный контроль

Добавляйте только людей, которым доверяете.

### 3. Защита ветки `main` (рекомендуется)

GitHub → репозиторий → **Settings → Branches → Add branch protection rule**

| Настройка | Значение |
|-----------|----------|
| Branch name pattern | `main` |
| Require a pull request before merging | ✅ (если работаете вдвоём — опционально) |
| Require status checks to pass | ✅ workflow **Deploy to GitHub Pages** / build |
| Do not allow bypassing | ✅ |
| Restrict who can push | только owner (+ доверенные) |

Тогда даже collaborator не сможет тихо сломать `main` без review (если включите PR).

### 4. Pull Request от незнакомцев

По умолчанию PR **не мержатся сами**. Владелец репо нажимает Merge.

**Не мержите** PR от незнакомых людей без проверки.

Settings → **General → Pull Requests** — можно включить «Automatically delete head branches».

### 5. GitHub Actions

Workflow `.github/workflows/deploy.yml` запускается на push в `main`.

- Секреты Actions — только **Settings → Secrets and variables → Actions**
- Не добавляйте в workflow `pull_request` с полным деплоем от forks без ограничений (у нас деплой только на `push` + `workflow_dispatch` — это безопасно)

### 6. Аккаунт GitHub

- Уникальный сильный пароль
- 2FA (app или ключ, не SMS если можно)
- Проверяйте **Settings → Security log** при подозрениях
- Не входите на GitHub по ссылкам из писем (фишинг)

## Защита на уровне сайта (уже в проекте)

В `seo/templates/head.html`:

- **Content-Security-Policy** — скрипты только с вашего домена (`script-src 'self'`)
- **X-Content-Type-Options: nosniff**
- **Referrer-Policy**
- **frame-ancestors 'none'** — сайт нельзя встроить в чужой iframe (clickjacking)

Чужой скрипт с Tilda/CDN на проде **не** подключён — меньше риска подмены контента через сторонние домены.

На своём сервере (nginx) — дополнительные headers: [DEPLOY.md](DEPLOY.md).

## Может ли кто-то «подделать» Culture Travel?

### Fork — не ваша угроза

Кто-то может склонировать репо и выложить **копию** на `другой-логин.github.io`.  
Это **не** ваш домен `culture-travel.ru` и **не** ваш официальный Pages URL.

Клиентам давайте только **официальный домен** и проверенные контакты.

### Подмена только если

1. Взломали **ваш** GitHub-аккаунт, или  
2. Вы сами добавили злоумышленника collaborator с Write, или  
3. Вы смержили вредоносный PR

→ поэтому 2FA + не давать Write всем подряд + не мержить чужие PR.

### Свой домен culture-travel.ru

Когда подключите домен — только **ваш** DNS у регистратора ведёт на **ваш** GitHub Pages.  
Чужой fork домен не перехватит.

## Формы и данные клиентов

Сейчас связь — Telegram, tel:, mailto:. Персональные данные на сайте **не собираются** в базу.

Когда появится CRM — секретные API-ключи **только** в GitHub Secrets / env на сервере, **не** в клиентском JS.

---

## Зависимости

На проде **ноль** npm-зависимостей. Node — только для сборки в CI.  
Меньше риска «взломали через чужую библиотеку».

## Если что-то пошло не так

1. GitHub → **Settings → Security log** — кто входил, что менял  
2. Отозвать подозрительные **Personal Access Tokens**  
3. Сменить пароль + перепроверить 2FA  
4. **Settings → Collaborators** — убрать лишних  
5. Откатить коммит в `main` или revert через GitHub UI  
6. При утечке token — Revoke немедленно, создать новый с минимальными правами (`repo` + `workflow` только если нужен push)

✅ Не храните токены и пароли в коде  
✅ Официальный сайт — только **culture-travel.ru** (когда подключите)
