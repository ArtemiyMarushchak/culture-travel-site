# Администрирование контента

Цель: менять тексты и фото **без правки вёрстки**.  
Правило: правите только данные (JSON / HTML программы) и картинки в `assets/`. Стили и блоки не трогайте, если не уверены.

После правок:

```bash
node tools/build.mjs
```

На проде: commit → push в `main` → сайт обновится сам.

Верстку «не сломаете», если:
- не удаляете кавычки и запятые в JSON;
- пути к фото начинаются с `/assets/...`;
- копируете готовый объект из шаблона, а не выдумываете новые поля наугад.

Проверить JSON можно в любом редакторе или на jsonlint.com перед сохранением.

## Карта JSON (зачем каждый файл)

| Файл / папка | Роль |
|--------------|------|
| `core/site.json` | Название, URL, телефон, email, реквизиты, соцсети |
| `core/nav.json` | Пункты меню шапки |
| `core/page-layout.json` | На каждой странице автоматически: шапка + подвал + модалки |
| `core/blocks.registry.json` | Список блоков сайта (для сборки CSS/JS) |
| `core/content-types.json` | Какие типы контента есть (новости, кейсы, отели) |
| `pages/*.page.json` | Страницы вроде главной, заглушек, приватной программы |
| `content/reviews/catalog.json` | Все отзывы на главной |
| `content/news/*.json` | Одна новость = один файл |
| `content/cases-slider/catalog.json` | Карточки в слайдере «Мои кейсы» |
| `content/cases/*.json` | SEO-страница кейса + ссылка на HTML программы |
| `content/cases/.../tour.html` | Текст и фото дней тура (публичный кейс) |
| `content/cases/.../program-full.html` | Полная программа (закрытая страница) |
| `content/hotels/*.json` | Отель: карточка + страница |
| `content/services/catalog.json` | Услуги на главной (текст + фото) |

## 1. Отзывы

Файл: `content/reviews/catalog.json`

1. Откройте файл.
2. В массив `items` добавьте копию соседнего отзыва.
3. Заполните поля:

```json
{
  "text": "Текст отзыва на русском",
  "textEn": "English text",
  "author": "Имя",
  "authorEn": "Name",
  "meta": "Направление · формат поездки",
  "metaEn": "Destination · trip type",
  "country": "za"
}
```

- `country` — код флага ISO: файлы в `assets/images/flags/` (полный набор SVG, напр. `za`, `it`, `fr`, `jp`).
- Своё фото вместо флага: `"photo": "/assets/images/reviews/guest.jpg"` (квадрат, лучше от 400×400).
- `pageSize` — сколько отзывов видно до кнопки «Показать ещё».

Верстка сама: 1 отзыв — на всю ширину, несколько — сетка. Лишние поля не добавляйте.

Медиа-правила (размеры/форматы): [ASSETS.md](ASSETS.md).

## 2. Новости

1. Скопируйте `content/news/_template.json` → например `content/news/my-news.json` (без подчёркивания в имени).
2. Положите обложку в `assets/images/news/` и пропишите путь в `cover`.
3. Заполните `slug`, `title`, `date`, `excerpt`, `body` (HTML абзацами `<p>...</p>`).
4. Соберите сайт.

Результат:
- карточка на главной в блоке новостей;
- страница `/news/ваш-slug/`.

Список `/news/` редиректит на главную к якорю новостей — это нормально.

## 3. Кейсы на главной (слайдер)

Файл: `content/cases-slider/catalog.json`

- Регионы — массив `regions`.
- Карточки лежат в `cases.africa`, `cases.asia` и т.д.
- Обязательные поля карточки: `title`, `text`, `image`.
- Если есть страница кейса: `"slug": "south-africa"` → кнопка ведёт на `/cases/south-africa/`.
- Без `slug` — только превью, без «Подробнее».

Фото кладите в `assets/images/cases/...`. Пока нет фото — можно `/assets/images/placeholder.svg`.

Слайдер не ломается от числа карточек: он рассчитан на список. Следите за запятыми в JSON.

## 4. Страница кейса и программа тура

Два уровня:

### A. Карточка / SEO-страница кейса

Файл вида `content/cases/south-africa.json`:
- метаданные (название, обложка, SEO);
- `bodyFile` — путь к HTML с текстом программы.

Пример публичного кейса: `/cases/south-africa/`.

### B. HTML программы (текст + фото по дням)

Файлы рядом с кейсом, например:
- `content/cases/south-africa/tour.html` — публичная версия;
- `content/cases/south-africa/program-full.html` — полная (для закрытой ссылки).

Как править без поломки вёрстки:
1. Откройте существующий день и **скопируйте** целый блок дня.
2. Меняйте только текст внутри и `src` у картинок.
3. Новые фото кладите в `assets/images/cases/south-africa/` (или папку своего кейса) и подставляйте путь.
4. Классы (`class="..."`) не переименовывайте и не удаляйте — от них стили.

Закрытая программа для туристов: страница `pages/south-africa.page.json` (сейчас `noindex`, URL `/south-africa/`). Она указывает на `program-full.html`.

Новый кейс «с нуля»:
1. Скопируйте папку кейса-образца и JSON.
2. Поменяйте `slug`, тексты, пути к фото.
3. Добавьте карточку в `cases-slider/catalog.json` с тем же `slug`.
4. Соберите сайт.

Шаблон-заготовка: `content/cases/_template.json` (для простых кейсов). Сложные программы удобнее клонировать с ЮАР.

## 5. Отели

1. Скопируйте `content/hotels/_template.json` → `content/hotels/my-hotel.json` (**без** `_` в начале имени).
2. Фото — в `assets/images/hotels/`, пути в массиве `media`.
3. `slug` латиницей без пробелов.

Файлы с `_` в начале (`_template.json`, `_example-hotel.json`) **не публикуются** — черновики.

Сборка даст страницу `/hotels/my-hotel/`.  
Список `/hotels/` сейчас заглушка (`noindex`). Когда будете запускать каталог: в `pages/hotels.page.json` поставьте блок `hotel-catalog` и уберите `"robots": "noindex"`.

## 6. Услуги

Файл: `content/services/catalog.json`

Каждая услуга: заголовок, короткий ярлык, текст, фото для десктопа и квадрат для телефона.

```text
image       → широкий кадр (десктоп)
imageMobile → квадрат 1:1 (модалка на телефоне)
```

Файлы: `assets/images/services/`. Имена лучше не менять без нужды — пути уже прописаны.

## 7. Контакты и меню

- `core/site.json` — телефон, email, Telegram, реквизиты, копирайт.
- `core/nav.json` — пункты меню. Неверный `href` просто ведёт «не туда», вёрстку не ломает.

## 8. Как устроена сборка (то, что вы уже заметили про CSS)

```text
pages + content + blocks  →  tools/build.mjs  →  dist/
```

- `styles/main.css` подключает токены, шрифт, UI и `blocks.css`.
- `blocks.css` собирается из реестра блоков автоматически.
- В браузер уходит уже готовый HTML со ссылками вида `/styles/main.css`.

Вам обычно не нужно править CSS, чтобы добавить отзыв или новость.

## Частые ошибки

| Ошибка | Что будет |
|--------|-----------|
| Забыли запятую в JSON | Сборка упадёт или страница без данных |
| Путь `/assets/...` без файла | Пустое фото / битая картинка |
| Изменили `class` в HTML программы | «Поплыла» вёрстка дня |
| Правили `dist/` вручную | Правки сотрутся при следующей сборке |

Всегда правьте исходники (`content/`, `assets/`, `core/`), потом `build`.
