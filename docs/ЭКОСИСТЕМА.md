# Экосистема Culture Travel — 4 репозитория, один домен

> Твой план: **не смешивать** проекты, но **один дизайн** везде.  
> Это меняет рекомендацию: shared tokens **нужны**, monorepo **опционален**.

---

## Карта на одном домене

```
culture-travel.ru              ← Репо 1: публичный статичный сайт
crm.culture-travel.ru          ← Репо 2: CRM (статика + Supabase)
app.culture-travel.ru          ← Репо 3: ЛК клиента (PWA / ярлык)
docs.culture-travel.ru         ← Репо 4: документация
```

DNS у регистратора — отдельная **CNAME**-запись на каждый поддомен (или один Cloudflare Pages project на app).

---

## Четыре репозитория — что где живёт

| # | Репозиторий | Поддомен | Стек | Кто видит |
|---|-------------|----------|------|-----------|
| 1 | `culture-travel-site` | `culture-travel.ru` | JSON + HTML + CSS + JS → static | Все, SEO |
| 2 | `culture-travel-crm` | `crm.culture-travel.ru` | Static + Supabase (auth, DB) | Только ты |
| 3 | `culture-travel-lk` | `app.culture-travel.ru` | PWA + Supabase | Клиенты |
| 4 | `culture-travel-docs` | `docs.culture-travel.ru` | Static docs (Starlight / VitePress) | Ты + команда |

**Правило:** код CRM **никогда** не попадает в репо 1. Ключи Supabase — **только** в репо 2 и 3 (через env на CI, не в git).

## Общий дизайн без смешивания проектов

Проблема: золото `#A8865E`, Montserrat, отступы — одинаковые везде.  
Если 4 репо **без связи** — при смене цвета правишь **4 раза**. Это и есть «смешивание через боль».

### Решение: пятый маленький репозиторий — только дизайн

```
culture-travel-design/          ← Репо 0 (общий, ~10 файлов)
├── tokens/
│   ├── colors.css
│   ├── typography.css
│   ├── spacing.css
│   └── interaction.css
├── fonts/
│   └── montserrat/             CDN или woff2
└── README.md
```

Каждый из 4 проектов **подключает** tokens одним способом (выбираем один):

| Способ | Плюсы | Минусы |
|--------|-------|--------|
| **Git submodule** | бесплатно, версия зафиксирована | `git submodule update` — чуть неудобно |
| **Копия при сборке** (CI) | просто в каждом репо | нужен скрипт sync |
| **npm GitHub Package** | `@culture-travel/tokens` | нужен Node, но один `npm update` |

**Моя рекомендация для тебя:** submodule или CI-копия — **0 ₽**, без npm registry.

В каждом приложении:

```css
@import url('./vendor/culture-travel-design/tokens/colors.css');
```

UI-компоненты (кнопки, заголовки) — **дублируем минимально** или тоже кладём в `culture-travel-design/ui/`.  
Блоки сайта (hero, cases) — **только в репо 1**, в CRM их нет.

## Monorepo vs 4 репо — честно под твой план

### Вариант A — 4 (5) отдельных репозиториев ✅ ближе к твоей голове

```
GitHub:
  culture-travel-site
  culture-travel-crm
  culture-travel-lk
  culture-travel-docs
  culture-travel-design   ← общие tokens
```

| Плюс | Минус |
|------|-------|
| CRM и сайт **физически разделены** | обновить tokens = commit в design + pull в 4 репо |
| разные права доступа (CRM private, site public) | 4 deploy workflow |
| психологически «не смешано» | |

### Вариант B — один monorepo с 4 apps

```
culture-travel/
├── apps/site/
├── apps/crm/
├── apps/lk/
├── apps/docs/
└── packages/design/    ← tokens один раз
```

| Плюс | Минус |
|------|-------|
| tokens меняешь **один раз** | всё в одном git — CRM рядом с сайтом |
| один CI, разные deploy targets | если public repo — CRM код виден (→ нужен private monorepo) |
| проще рефакторинг дизайна | |

### Моя рекомендация

| Если | Бери |
|------|------|
| Хочешь **строго 4 репо**, CRM **private**, сайт **public** | **A + design repo** |
| Готов к **одному private monorepo** | **B** — меньше возни с tokens |

**Оба варианта нормальные.** Ты описала A — **делаем A**, с `culture-travel-design` для общего стиля.

Deploy: GitHub Pages / Cloudflare → `culture-travel.ru`

---

## Репо 2 — CRM (позже)

```
culture-travel-crm/
├── static/                 HTML/CSS/JS панель
├── supabase/
│   └── migrations/         схема БД (версионируется)
└── .env.example            без секретов в git
```

- **Supabase Free:** 500 MB DB, auth, RLS — хватит на старт
- **SEO:** `robots: noindex` — Google не индексирует CRM
- **Безопасность:** только Supabase Auth, Row Level Security, HTTPS
- Подключает **те же tokens** из `culture-travel-design`

Deploy: `crm.culture-travel.ru` — **private** repo + Cloudflare Pages (бесплатно)

---

## Репо 3 — ЛК клиента / PWA (позже)

```
culture-travel-lk/
├── src/                    экраны: поездки, документы, чат
├── manifest.webmanifest    «добавить на экран»
├── sw.js                   service worker (офлайн-оболочка)
└── supabase client         те же пользователи/данные что CRM, другие RLS-политики
```

- Ярлык на телефон = PWA, не App Store (бесплатно)
- Дизайн из `culture-travel-design`
- Deploy: `app.culture-travel.ru`
