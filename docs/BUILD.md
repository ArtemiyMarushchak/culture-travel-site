# Сборка и локальный просмотр

Нужен **Node.js 18+** (рекомендуется 20 — как в CI).  
**Python в проекте нет** и не нужен: ни `build.py`, ни иных скриптов на Python.

---

## Быстрый старт

```bash
# из корня репозитория
node tools/build.mjs      # собрать сайт в dist/
node tools/preview.mjs    # открыть локальный просмотр dist/
```

Или одной командой:

```bash
npm run preview           # build + preview подряд
```

Другие npm-скрипты (`package.json`):

| Команда | Что делает |
|---------|------------|
| `npm run build` | Только сборка → `dist/` |
| `npm run dev` | Сборка в режиме `--watch` (пересборка при изменениях) |
| `npm run preview` | Сборка + локальный сервер |

---

## Что делает `build.mjs`

Читает исходники и пишет готовый сайт в `dist/`:

1. Страницы из `pages/*.page.json`
2. Контент из `content/`
3. Блоки из `blocks/` (+ secondary)
4. Копирует `assets/`, собирает CSS/JS
5. Генерирует служебные файлы:
   - `robots.txt`
   - `sitemap.xml`
   - `llms.txt`
   - `404.html`
   - `site.webmanifest`
   - при деплое с доменом — `CNAME`

В браузер уходит уже готовый HTML со ссылками вида `/styles/main.css`.

```
pages + content + blocks + assets
              ↓
       tools/build.mjs
              ↓
            dist/
```

---

## Что делает `preview.mjs`

Поднимает простой локальный HTTP-сервер над папкой `dist/`, чтобы открыть сайт в браузере так же, как на проде (пути `/assets/...`, `/news/...` и т.д.).

Без preview можно открыть файлы с диска — но часть путей и роутинга может вести себя иначе. Для проверки всегда используйте preview или аналог.

---

## Рабочий цикл правок

1. Меняете JSON / HTML / фото в `content/`, `assets/`, `core/`.
2. Запускаете `node tools/build.mjs` (или `npm run dev` с watch).
3. Смотрите в preview.
4. Если всё ок — commit → push в `main` (см. [DEPLOY.md](DEPLOY.md)).

На GitHub сборка повторится сама в Actions — локальный build перед push желателен, чтобы поймать ошибки JSON заранее.

---

## Типичные ошибки сборки

| Симптом | Причина | Что делать |
|---------|---------|------------|
| Сборка упала на JSON | Запятая, кавычки, битый синтаксис | Проверить файл в редакторе / jsonlint |
| Пустое фото | Путь в JSON есть, файла нет | Положить файл или поправить путь |
| Старая версия в браузере | Смотрите не `dist/`, или кэш | Пересобрать + hard refresh |
| Правки «пропали» | Правили `dist/` | Править исходники, снова `build` |

## Переменные окружения (CI / продвинутое)

На GitHub Actions (см. `.github/workflows/deploy.yml`) при сборке задаются:

| Переменная | Смысл |
|------------|--------|
| `GITHUB_PAGES=true` | Режим Pages |
| `CUSTOM_DOMAIN=true` | Apex-домен culture-travel.ru: пустой `basePath` + `CNAME` в `dist/` |

Локально обычно **ничего** выставлять не нужно.
